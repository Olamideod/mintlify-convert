# Component Mapping Reference

This document provides a comprehensive reference for how Mintlify Convert transforms various markdown patterns into Mintlify components.

## Overview

Mintlify Convert automatically recognizes patterns in your MDX content and converts them to appropriate Mintlify components. This mapping ensures your documentation looks great and functions properly in Mintlify.

## Callouts (Blockquotes)

### Input Pattern
```markdown
> **Warning:** This is important information.
> Please read carefully.

> **Tip:** Here's a helpful suggestion.
> Try this approach for better results.
```

### Output
```mdx
<Warning>
**Warning:** This is important information.
Please read carefully.
</Warning>

<Tip>
**Tip:** Here's a helpful suggestion.
Try this approach for better results.
</Tip>
```

### Supported Types
- `<Warning>` - For warnings, cautions, and important notices
- `<Tip>` - For tips, hints, and best practices
- `<Note>` - For general notes and reminders
- `<Info>` - For informational content
- `<Check>` - For success and confirmation messages

## Steps (Numbered Lists)

### Input Pattern
```markdown
1. Install the package
2. Configure your API key
3. Run your first request
```

### Output
```mdx
<Steps>
  <Step title="Install the package">
  Install the package
  </Step>
  <Step title="Configure your API key">
  Configure your API key
  </Step>
  <Step title="Run your first request">
  Run your first request
  </Step>
</Steps>
```

Step titles come from the step text. Leading words such as "First", "Next", "Then", "Finally" and "Step N:" are removed from the title. Titles are plain text (no backticks or `**` markers) and, for long steps, end at a clause or word boundary at about 80 characters. The full step text stays in the step body.

One numbered list becomes one `<Steps>` block. A list continues across blank lines and across code fences or indented content between numbered items; that content belongs to the preceding step. The list ends at the first non-blank line that is not indented and not numbered.

## Tabs (Language-Specific Code)

### Input Pattern
````markdown
JavaScript:
```javascript
const api = require('api');
api.get('/users');
```

Python:
```python
import api
api.get('/users')
```
````

### Output
````mdx
<Tabs>
  <Tab title="JavaScript">
```javascript
const api = require('api');
api.get('/users');
```
  </Tab>
  <Tab title="Python">
```python
import api
api.get('/users')
```
  </Tab>
</Tabs>
````

Tabs are built from a language label followed by a fenced code block. Consecutive labelled blocks form one `<Tabs>` group, and a group needs at least two blocks. Unfenced `Label:` lines work for some languages (JavaScript, Python) but not all (for example Node.js is not recognised), so prefer fenced code.

### Supported Languages
- JavaScript
- Python
- TypeScript
- Ruby
- Go
- Java
- PHP
- Curl (title shown as "cURL")

## Accordions (H3 Sections)

Only H3 sections whose title contains one of these keywords (case-insensitive) become accordions: troubleshooting, FAQ, frequently asked, advanced, common issues, known issues, error codes, walkthrough, step by step, breakdown. Other H3 sections stay as headings. An accordion ends at the next heading of any level.

### Input Pattern
```markdown
### Advanced Configuration
This section contains detailed configuration options
that can be collapsed for better readability.

You can customize various settings here.
```

### Output
```mdx
<Accordion title="Advanced Configuration">
This section contains detailed configuration options
that can be collapsed for better readability.

You can customize various settings here.
</Accordion>
```

## Banners (Top-Level Notices)

Only a paragraph that starts with `Deprecated:`, `Important:`, `Notice:` or `Alert:` (optionally preceded by an emoji) is converted. The same text in the middle of a paragraph is left alone.

### Input Pattern
```markdown
⚠️ Deprecated: This endpoint will be removed in v2.0

🚨 Important: Maintenance scheduled for tonight at 10 PM
```

### Output
```mdx
<Banner type="warning">
  This endpoint will be removed in v2.0
</Banner>

<Banner type="warning">
  Maintenance scheduled for tonight at 10 PM
</Banner>
```

### Supported Types
- `warning` - For deprecated features, maintenance notices
- `info` - For general announcements

## Cards (Help Sections)

### Input Pattern
```markdown
Need help?

Contact our support team
or check our FAQ section.

Questions?

Feel free to reach out if you have any questions.
```

### Output
```mdx
<Card title="Need help?" icon="help-circle">
  Contact our support team
or check our FAQ section.
</Card>

<Card title="Questions?" icon="question">
  Feel free to reach out if you have any questions.
</Card>

The icon is chosen from the title and text, so it varies. A help card is only recognised when its title line starts a paragraph.
```

## API Links

### Input Pattern
```markdown
[Get Users](/api/#operation/getUsers-v1)
[Create User](/api/#operation/createUser-v1)
```

### Output
```mdx
[Get Users](/api-reference/getUsers-v1)
[Create User](/api-reference/createUser-v1)
```

## Docusaurus Syntax

The tool rewrites these Docusaurus patterns before it applies the rules above.

### Admonitions

````markdown
:::tip[Use tabs]

Text with `code`.

:::
````

becomes:

```mdx
<Tip>

**Use tabs**

Text with `code`.

</Tip>
```

The types `note`, `tip`, `info`, `warning`, and `danger` map to the callout with the same name. `caution` becomes `<Warning>`, and `success` and `secondary` become `<Check>` and `<Note>`. An unknown type becomes `<Note>` with a warning. An admonition that never closes stays as written.

### Tabs

```mdx
<Tabs groupId="pm">
  <TabItem value="npm" label="npm" default>

npm install

  </TabItem>
</Tabs>
```

becomes `<Tabs>` with `<Tab title="npm">`. The tool takes the title from `label`, or from the `values` prop on `<Tabs>`, or from `value`. A `default` item or a `defaultValue` prop sets `defaultTabIndex`.

### Details

`<details><summary>Title</summary>` becomes `<Accordion title="Title">`, and `<details open>` adds `defaultOpen`.

### Code blocks

| Input | Output |
| --- | --- |
| `showLineNumbers` | `lines` |
| `{1,3-5}` | `highlight={1,3-5}` |
| `// highlight-next-line` | Comment removed, next line highlighted |
| `// highlight-start` and `// highlight-end` | Comments removed, lines between them highlighted |
| `title="a.js"` | Kept |

The magic comments also work with `#`, `/* */`, `{/* */}`, and `<!-- -->`.

### Imports, comments, and heading ids

- `import` lines are removed, except imports from `/snippets/`.
- `<!-- text -->` becomes `{/* text */}`.
- `## Title {#id}` and `## Title {/* #id */}` become `## Title`.

### Frontmatter

`sidebar_label` becomes `sidebarTitle`. These keys are dropped: `id`, `slug`, `sidebar_position`, `sidebar_class_name`, `pagination_*`, `hide_*`, `toc_*`, `displayed_sidebar`, `tags`, `image`, and `draft`. `sidebar_position` still sets the page order in `docs.json`.

## Relative Links

Relative links to `.md` and `.mdx` files are rewritten to root-relative paths without the extension, for example `[Other](other.mdx)` becomes `[Other](/other)`. A relative link that resolves outside the input directory (for example `../examples/`) is left unchanged.

## Images

### Input Pattern
```markdown
![API Flow](diagrams/api-flow.png)
![Logo](assets/logo.svg)
```

### Output (with --download-assets)
```mdx
<Frame>
  <img src="/images/api-flow.png" alt="API Flow" />
</Frame>
<Frame>
  <img src="/images/logo.svg" alt="Logo" />
</Frame>
```

Image rules:

- Images are copied when you convert a directory. With `--no-assets` (or when converting one file without `--download-assets`), image links are left as written.
- The source image must be inside the input directory. Absolute paths, `file:` and `data:` URLs and `//` URLs are not copied.
- Only common image file types are copied. Symlinks are skipped.
- An image with a `file:` source is not copied, and a warning is printed to stderr.
- Copied files go to `/images` using the file name only.

## Frontmatter Generation

### Input Pattern
```markdown
# Getting Started with Our API

Welcome to our comprehensive API documentation.
```

### Output
```mdx
---
title: "Getting Started with Our API"
description: "Welcome to our comprehensive API documentation."
---

Welcome to our comprehensive API documentation.
```

## Idempotence and code fences

Converting already-converted output yields the same output. Content inside fenced code blocks is never transformed. A callout, banner or step list whose first line is a code fence is left unconverted.

## Custom Patterns

You can extend Mintlify Convert to recognize custom patterns by subclassing the `MintlifyConverter` class:

```python
import re

from mintlify_convert import MintlifyConverter

class CustomConverter(MintlifyConverter):
    def convert_custom_pattern(self, content: str) -> str:
        """Convert custom patterns to Mintlify components."""
        # Your custom logic here
        pattern = r'\[CUSTOM\]\s*(.+?)\[/CUSTOM\]'
        replacement = r'<CustomComponent>\1</CustomComponent>'
        return re.sub(pattern, replacement, content)
    
    def convert(self, content: str, **kwargs):
        """Override main convert method to include custom patterns."""
        content = self.convert_custom_pattern(content)
        return super().convert(content, **kwargs)
```

## Best Practices

1. **Use consistent formatting** - Stick to standard markdown patterns for best results
2. **Test your conversions** - Always validate output with `--validate` flag
3. **Review component mappings** - Check that conversions match your expectations
4. **Customize as needed** - Extend the converter for project-specific patterns

## Troubleshooting Mappings

### Common Issues

**Issue**: Callouts not converting properly
**Solution**: Ensure blockquotes start with `>` and include keywords like "Warning:", "Tip:", etc.

**Issue**: Steps not converting
**Solution**: Use numbered lists (1., 2., 3.) with proper spacing

**Issue**: Tabs not working
**Solution**: Use exact language names followed by colon (JavaScript:, Python:, etc.)

**Issue**: Images not copying
**Solution**: Use `--download-assets` and ensure the images are inside the input directory
